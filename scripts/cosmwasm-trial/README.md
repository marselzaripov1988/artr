# Проба CosmWasm

Ветка `experiment/cosmwasm`. Это **проба**, а не готовая интеграция, и
сливать её в рабочую ветку нельзя — см. «Что мешает слиянию» ниже.

Цель пробы была узнать цену вопроса, а не получить рабочий продукт:
подключается ли CosmWasm к Artery со своим банком и без стейкинга,
сколько это стоит и где упирается. Ответы получены и проверены на живой
сети; подробный разбор — в отчёте по предложению про ИИ-вычисления.

## Что получилось

Работает: узел собирается и стартует, контракт загружается, экземпляр
создаётся с переводом средств, запрос к контракту отвечает, контракт
отправляет монеты обратно. Паник за прогоны ноль.

| | |
|---|---|
| `wasmd` | v0.60.8 — рассчитан ровно на SDK 0.53 |
| Версии | ни одна наша не понизилась: SDK 0.53.8, CometBFT 0.38.26, ibc-go v10.7.0 |
| Размер `artrd` | 134 МБ → 155,6 МБ |
| Рядом | `libwasmvm.x86_64.so`, 8,3 МБ |

## Из чего состоит

| Файл | Что делает |
|---|---|
| `app/wasm_trial.go` | переходник банка (6 методов сверх написанных для IBC) и заглушки стейкинга с распределением — их в Artery нет вовсе |
| `app/wasm_bank_msg.go` | кодировщик банковских сообщений: исходящие переводы из контрактов идут в банк Artery, а не в `cosmos.bank`, которого в сети нет |
| `app/app.go` | ключ хранилища, поле, создание кеепера, модуль в менеджере, три списка порядка, регистрация в `ModuleBasics`, право счёта на сжигание |

## Как собрать

Ветка **не вендорится**: `wasmvm` тянет за собой два двоичных файла по
8 МБ, и класть их в `vendor/` ради пробы незачем. Поэтому обычная
`go build` в корне упрётся в несогласованный `vendor/`.

Собирать так — CGO обязателен, Go строго из `go.mod`:

```sh
docker run --rm -v "$PWD":/src -w /src golang:1.23.8 bash -c \
  'GOFLAGS=-mod=mod CGO_ENABLED=1 go build -o artrd-wasm ./cmd/artrd'
```

**Сборка без CGO выглядит успешной и даёт нерабочий файл.** В wasmd
рядом с `keeper_cgo.go` лежит `keeper_no_cgo.go` с той же сигнатурой и
телом из одной строки `panic("not implemented, please build with cgo
enabled")`. `go build` проходит, CI зелёный, узел умирает при старте.

Двоичный файл линкуется динамически, и путь к библиотеке впаивается
**абсолютный, из каталога кэша модулей сборочной машины**. Скопировать
его на другую машину нельзя — нужно нести рядом `libwasmvm.x86_64.so`
и ставить `LD_LIBRARY_PATH`. Штатный выход — статическая сборка с musl,
но `libwasmvm_muslc.a` в модуле нет, её качают из выпусков wasmvm.

## Как проверить

Скрипты рассчитаны на запуск в контейнере с примонтированными
`/work` (это дерево), `/devnet` (`devnet/scripts` из репозитория
`crypto` — нужен `conspub.py`) и `/template` (каталог `app/`, там
`test-genesis.json`).

| Скрипт | Что делает |
|---|---|
| `setup-only.sh` | готовит генезис и **не шлёт ни одной транзакции** |
| `run-full.sh` | полный цикл на `hackatom`: загрузка, экземпляр с монетами, запрос, вызов |
| `run-reflect.sh` | перевод на заданную сумму — главная проверка исходящих переводов |
| `diag-seq.sh` | служба счетов: REST, ABCI, две транзакции подряд |

Почему `setup-only.sh` не шлёт транзакций: последовательность счёта
приходится вести вручную, и каждая лишняя транзакция в подготовке
сбивает нумерацию в проверке.

## Что надо знать про комиссию

Перевод из контракта идёт **сообщением** через банк Artery, а не прямым
вызовом `SendCoins`. Значит, контракт платит комиссию за перевод как
обычный отправитель.

Это намеренно: прямой вызов комиссию бы обошёл, и контракты стали бы
путём вывода крупных сумм мимо неё.

Следствие: **контракт не может отдать весь свой баланс** — надо
оставлять запас. Готовые контракты из экосистемы CosmWasm часто
написаны в расчёте на «отправить всё»; в Artery их придётся править.
Именно поэтому `hackatom` на `release` падает, и это правильное
поведение.

## Что мешает слиянию

1. **CGO не включён в сборках.** `devnet/Dockerfile` в `crypto` собирает
   с `CGO_ENABLED=0` — образы стали бы тихо нерабочими.
2. **Раздача `libwasmvm` не решена.** Статическая сборка с musl плюс
   контрольная сумма, и зависимость от чужих выпусков.
3. **Тестов нет ни одного.** Ни на переходники, ни на заглушки, ни на
   кодировщик. Всё проверено ручными прогонами.
4. **Домашний путь берётся из окружения.** `NewArteryApp` его не
   принимает, а `x/wasm` требует каталог под кэш контрактов. Для
   настоящей интеграции путь надо протащить через конструктор.
5. **Решения о CosmWasm нет.** Нужен ли он безотносительно ИИ — вопрос
   стратегии проекта, и он не решён.

## Ловушка в переходнике

У Artery `GetBalance` возвращает **все** монеты счёта, а в SDK — одну,
по деному. Одинаковое имя при разном смысле: переходник, написанный
«по очевидному», собрался бы и молча врал. Типы сходятся, компилятор не
поможет.
